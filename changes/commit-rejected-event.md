## Why

Повторяющийся инцидент 2026-08-23: хук отклоняет коммит, агент продолжает по «echo OK»/мимо stderr и «ждёт», путая состояние. Причина — у отказа нет машинного сигнала, который невозможно пропустить. Туловый вариант (поднят из _backlog): хук при отказе пишет событие в ленту — плагин-консьюмер или сам агент (caped events) видят факт, не парся tool-log. Гейт остаётся ДО (энфорсмент), событие — факт ПОСЛЕ; нотификация не приравнивается к энфорсменту (как в #event-feed).

## Context

Лента v0 есть (feed.jsonl, post-commit эмиттер, `caped events --since`). Недостающее звено: пост-коммит не срабатывает при отказе — коммита нет. Значит писать отказ должен сам хук-гейт в момент валидационных ошибок (stream-эндфлорить: тот же append, та же атомарность одна строка). Диспатч .caped/hooks/commit-rejected — тот же механизм emit; активных хуков на него нет — плагин поллит ленту по курсору. Плагинский детект tool-логов сессии («commit-msg: rule violations») — их территория, тут только туловый факт.

## Requirements

- commits-gewait: при непустых валидационных ошибках (перед exit 1) — строка `{"t":"commit-rejected",...}` в `.caped/events/feed.jsonl` (одна строка = один append, как emit; mkdir -p при необходимости).
- Диспатч `.caped/hooks/commit-rejected` (exec + CAPED_EVENT/CAPED_ENTITY/CAPED_COMMIT) — та же семантика emit.
- README `#event-feed` перечисляет типы с commit-rejected; дамп events-строка дополнена.
- Тест (events-сьют): невалидный коммит → в ленте commit-rejected; валидный → нет.
- just test зелёный.

## Rejected alternatives

- Только плагин-детект тул-логов — недостаточен для одного: агент без плагина (adopting-репо или CLI) не получает сигнала; туловый факт в ленте доступен всем. Плагин-наг — дополнение, не замена.

## Provenance

Человек (дословно): «по проверке коммита надо идею сделать нормальную и видимо реализовать сразу».

Додумано агентом (с основаниями):

- Отказ пишет сам гейт — основание: факты ленты пишутся там, где случаются; пост-коммит при отказе не существует; append из хука — тот же атомарный путь.
- Гейт остаётся гейтом (ДО), событие — фактом (ПОСЛЕ) — основание: модель «нотификация ≠ энфорсмент» из событийной нормы; хук не становится мягче.
