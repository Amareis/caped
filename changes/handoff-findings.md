## Why

SPAWNING IDEAS описывает три маршрута находки — расширение своего контракта, новая идея, адхок — но не четвёртый: находка, адресующая СУЩЕСТВУЮЩИЙ контракт другой сущности (другого капа / идеи / чейнджа). Механика существует (Spec: на правку спека, дельты при архивации, #req-form), моста нет: «решили в A, живёт в B» держится только прозой променанса и доброй волей секретаря; забыл — требование тихо умирает, класс «отложили молча = потеряли». Живой кейс: O5 в adhoc-lifecycle (выдержка тел адхоков в history) — адресат render-format; без правила передача — ручной шаг без следа.

## Context

Grep по правилам («чуж/handoff/передач») — пусто: ни в README, ни в дампе сценарий не описан. «Расширение vs новая идея» покрывает свой-контракт и новую территорию; «вывод в чужой существующий контракт» — промежуток между ними. Применение правила — сам O5: правка changes/render-format.md + запись в променанс источника (adhoc-lifecycle).

## Rejected alternatives

- Адхоком без файла — отвергнуто: новое правило = новая территория решений, трогает дамп + README + применение, несёт открытые вопросы (машинный след, e2e-покрытие) — признаки файла по SPAWNING IDEAS.
- Машинное обязательство с v0 (caped check ворнит: «в променансе сказано handed off → B, а в B нет следа») — отложено в открытый вопрос: проза + конвенция проверяемы ревью, доп-налог чекер-ворнинга не оправдан на малом корпусе.

- «Ну то есть получается это просто изменение/добавление требования в другой капабилити? В целом логично для идеи/чейнджа ведь. У нас такой воркфлоу не описан что ли?»
- «Мммм... Получается 1 пункт это уже отдельный чейндж получается, причем важный? Адхоком его нельзя проводить по твоим же правилам? Ну да, все правильно - делай тогда, второй агент пока на стопе»

Додумано агентом (с основаниями):

- Файл, не адхок — основание: новое правило (новая территория решений), несколько капов (scripts/caped.sh, README.md, применение на render-format), открытые вопросы — любой из признаков отдельно требует файл; «адхок обсуждённое ≤2 коммитов» здесь не выполняется.
- spawned_from: complete-rules-dump — основание: территория полноты дампа правил, прямой предшественник (архивный чейндж аудита дампа); продолжение той же территории.
- no-test + dump — основание: конвенция секретарского поведения (процессная, не машинопроверяемая в v0), но агент-фейсинг — обязана быть в дампе; e2e-сценарий передачи — открытый вопрос, харнесс secretary дороже одной конвенции для v0.
