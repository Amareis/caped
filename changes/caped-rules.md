## Зачем

Правила работы с репо (лайфцикл, трейлеры, события) сейчас вычитываются из 300 строк корневого README — агент
узнаёт о них постфактум, от отказа хука. Правила должны жить в самом туле и выдаваться по требованию: единый
источник, версионируемый с кодом, без дрейфа markdown-копий.

## Контекст

Прецеденты: OpenSpec держит правила в длинных AGENTS.md + скиллах (маркдаун, дрейфует отдельно от кода);
beads — `bd prime`, дамп воркфлоу из самого CLI. Выбираем путь beads. В v0 нет бинаря — диспетчер
`scripts/caped.sh` играет его роль и заодно становится точкой, на которую позже перейдут шимы
(`exec caped hook commit-msg`). Конвенций по коду в репо пока нет, поэтому AGENTS.md — стаб из одной
инструкции, а не документ.

## Требования

1. `scripts/caped.sh` без аргументов печатает полные правила: лайфцикл (идея → в работу → работа → архив),
   справку по трейлерам (`Behavior`/`Spec`/`Idea`/`Change`/`Archives`), состояния реестра, дисциплину
   (атомарность, чистый mv, «чат эфемерен — променанс нет»), подкоманды.
2. Подкоманды: `init` (делегат caped-init.sh), `hook <name>` (делегат hooks/<name>), `check`/`materialise` —
   заглушки «не реализовано» с exit 1.
3. `caped-init.sh` ставит шим вида `exec .../scripts/caped.sh hook commit-msg "$@"` (форма v0.1 уже сейчас).
4. AGENTS.md в корне — стаб: «первым делом запусти scripts/caped.sh без аргументов и следуй выводу».
5. Текст правил — на русском, самодостаточный: агент, прочитавший только его, ведёт репо без ошибок хука.

## Решения

По слепому тесту (сабагент, только AGENTS.md + bare-вывод, ~80% понимания) в дамп внесены уточнения, не меняющие
семантику: дамп явно отправляет читать `caped.registry`; архивное правило переформулировано («не мешай с
ПОСТОРОННИМИ правками; дельты спек — это и есть контент архивного коммита»); `Spec:` — «трейлер ИЛИ файл спеки
в коммите, хук принимает любое»; `Behavior:` распространён явно и на архивный коммит; `init` помечен
идемпотентным; `phase`/`priority` объявлены свободными advisory-полями v0.

По решению человека секции идеи/чейнджа унифицированы (Зачем/Контекст/Требования/Решения/Променанс/Открытые
вопросы + опциональные секции внизу чейнджа, типично Задачи) — mv в работу становится по-настоящему чистым,
переходный коммит реструктуризации исчезает.

По вопросу человека «находки внутри чейнджа — расширение или новая идея» добавлено правило: правка того же
контракта — расширение (тот же `Change:`), новая территория решений — идея со `spawned_from`. Сами эти правки —
первое применение правила: все они вошли расширением в `caped-rules`.

## Променанс

Человек: «вызов caped без аргументов сразу вываливает все правила — тогда можно в agents указать, чтобы его
первым делом вызывали, тогда всё в коде фиксируется»; «в agents.md нечего больше фиксировать — конвенций по
коду особо нет».

Агент (основания): аналогия `bd prime` (beads) — единственный известный прецедент rules-in-CLI; контраст с
OpenSpec (правила в маркдауне, дрейф) — по истории kudach write-only слои без потребителя умирают; заглушки
check/materialise в диспетчере сразу — чтобы AGENTS.md и мышечная память агентов не менялись при их появлении.

## Открытые вопросы

- Дублирование: текст правил в caped.sh и сообщения ошибок хука — два источника одной семантики. В v0.1
  (бинарь) хук зовёт тот же код; в v0 принимаем дубль, хук ссылается «полные правила: scripts/caped.sh».
