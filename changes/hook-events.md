## Зачем

Модель обещает «вся работа восстановима из истории гита», но v0-хук проверяет только `Behavior`/`Spec` —
события жизненного цикла (рождение идеи, взятие в работу, архивация) остаются добровольной дисциплиной, а
добровольное разъезжается. Хук должен энфорсить события так же, как классы.

## Контекст

Требование записано в корневом README («События жизненного цикла — энфорсмент на коммитах»); там же честно
оговорено, что v0 покрывает подмножество. Эта идея — закрытие разрыва. Хук — bash, ~84 строки; рост оценён в
+40 строк. Ограничение: хук обязан оставаться быстрым (bash-класс старта) и самопочиняемым (сообщения об
ошибке = инструкция агенту).

## Требования

Хук дополнительно проверяет (по `git diff --cached --name-status -M`):

1. Добавленный `ideas/<name>.md` → трейлер `Idea: <name>`, совпадающий с именем файла. Если есть ещё и
   `Change: <parent>`, то `changes/<parent>.md` обязан существовать (порождённая идея не ссылается в никуда).
2. Rename `ideas/X.md` → `changes/X.md` → трейлер `Change: X`, совпадающий с именем. Добавление
   `changes/X.md` НЕ через rename (статус `A`) отклоняется — чейндж рождается только взятием идеи в работу
   (исключение: `Change: init` у семенного коммита adopting-репо).
3. Трейлер `Change: X` без `Archives: X` → `changes/X.md` существует в индексе (нельзя сослаться на
   несуществующий чейндж).
4. Удалённый `changes/X.md` (статус `D`) → трейлер `Archives: X`, совпадающий с именем. И обратно:
   `Archives: X` без удаления файла отклоняется.

Проверки глобальны (трекер-зона `ideas/`/`changes/` вне реестра капов) и работают независимо от
Behavior-ветки. Чистоту mv (similarity 100%) не энфорсим: фронтматер на mv не меняется, но заставлять —
лишняя строгость; rename detection по умолчанию (50%) достаточно.

## Променанс

Человек: «это тоже надо всё энфорсить на коммитах сразу»; «это получается как раз первая идея же? Давай по
воркфлоу её веди сразу» — то есть сама идея ещё и первый прогон воркфлоу на себе.

Агент (основания): исключение `Change: init` — иначе adopting-репо не сделать семенной коммит (из требования
бутстрапа корневого README); проверки через `--name-status -M`, а не `--name-only` — иначе rename от add не
отличить; отказ от энфорсмента similarity 100% — в README «чистый mv» сформулирован как дисциплина, хук
проверяет факт rename, а не его стерильность (граница «хук vs совесть» по аналогии с тем, что хук не проверяет
контент спеки).
