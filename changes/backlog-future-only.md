## Why

Политика «витрина только будущих мыслей» существовала в истории (чистки 1f9d0ac,
3bf9599) и в тексте `_backlog.md`/дампе, но не как требование спеки: в reqs-индексе
её нет, для новых агентов заметна только через историю. Человек подтвердил:
оформить маркером.

## Context

2026-08-24: политика вписана в `_backlog.md` (Context) и дамп (SPAWNING), оба как
процессный текст. Для машинопроверяемости нужен деф в README: `[#backlog-future-only
no-test dump]` — `no-test` (процессная конвенция, теста нет), `dump` (правило
агент-фейсинг: агенты ведут бэклог и должны видеть его в дампе).

## Requirements

- README получает буллет `[#backlog-future-only no-test dump]`: витрина forward-only —
  применённое/переданное из строк убирается, следы живут в гит-истории, (статус) в
  строке — сигнал к чистке, не журнал.
- Дамп ссылается на маркер (текст будущей-only уже есть в SPAWNING — добавить
  `[#backlog-future-only]` к фразе).

## Decisions

- `no-test`: правило процессное (записная дисциплина), сценария нет — как у
  остальных конвенций.
- `dump`: правило агент-фейсинг, обязано быть в дампе (там уже есть текст — нужен
  только маркер).

## Rejected alternatives

- Оставить процессным текстом: попадает в историю, но не в reqs-индекс и не
  переживает реорганизацию бэклога. Отклонено человеком («Да, надо»).
- `{... dump}` без no-test: потребовало бы тест-сценария для процессной конвенции.
  Отклонено.
