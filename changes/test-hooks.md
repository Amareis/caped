## Зачем

Хук — единственный энфорсер модели; его регрессия подрывает всё. Сейчас сценарии прогоняются руками при
изменении хука (так делалось в hook-events) — воспроизводимости нет.

## Контекст

Сценарии уже дважды прогонялись вручную: behavior-ветка (отказ без трейлера, wip-subject, contract без Spec)
и событийная (рождение идеи, прямое добавление чейнджа, mv, правка, архивация, Change на несуществующий,
Archives без удаления, init-исключение).

## Требования

1. `scripts/test-hooks.sh` гоняет все сценарии против временного git-репозитория (свой init, свой индекс —
   рабочее дерево не трогаем), печатает PASS/FAIL по каждому, exit 1 при любом FAIL.
2. Покрытие: behavior (нет трейлера / wip-subject / internal / contract без Spec / contract с Spec / contract
   со spec-файлом в коммите) и события (A ideas/ без Idea / чужой Idea / A changes/ напрямую / init-исключение /
   R ideas→changes без Change / rename со сменой имени / M changes/ без Change / D changes/ без Archives /
   Change на несуществующий / Archives без удаления).
3. Входит в verify рядом с check.

## Решения

Реальные коммиты во временном репо (не прямые вызовы хука): тестируем ровно то, что видит пользователь, включая
цепочку шим → диспетчер → хук; фикстурные коммиты — `--no-verify`. Первый прогон поймал реальный баг:
эвристика тела adhoc-коммита вырезала любые trailer-образные строки и съедала честное тело («rationale: …») —
чинено вычитанием настоящего trailer-блока через `git interpret-trailers --only-trailers`. Это мини-подтверждение
самой идеи: сценарии, записанные до кода, ловят то, что ручной прогон пропустил.

## Променанс

Агент: хук вырос до ~160 строк с двумя ветками логики; ручные прогоны уже дважды были частью работы —
механизация напрашивается (аналогия: e2e-харнесс kudach, который окупился именно на регрессиях).
Человек: «создай папку с тестами — это же реально всё по процессу получается, буквально на каждую идею нужен
свой тест-кейс» — обобщено в правило лайфцикла: архивация оставляет сценарии в тестах (см. корневой README).
