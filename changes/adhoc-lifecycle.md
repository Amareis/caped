## Why

Адхок — «дверь без ручки»: войти легко, выйти не за что. В истории это видно: 13 fileless-адхоков против 10 архивов; кластеры по одной территории (c8fcd49→e20449f→5c9d71a→0be5ac5→5367bc4 — пять fileless на Spec: README.md); новые требования оформлялись адхоком (5367bc4 ввёл [#render-history-adhoc], 578190d — [#dump-neutrality], оба без файла); метрика шумит на событиях (ренейм materialise→render, a11d6e6, посчитан адхок-решением из-за Behavior + задетого README); тела — единственный носитель ратионале — в рендере не видны (только дата/хэш/сабжект). Граница «>2 коммитов» держится совестью и паккуется. Нужен: именованный, видимый, машинно-ограниченный жизненный цикл адхока.

## Context

Два механизма делают замысел машиночистым: (1) `Adhoc: <name>` — явный трейлер: сообщения коммита = виртуальный документ чейнджа (эскалация = переезд тел в файл, не переписывание); id резолвится как spawned_from (новый = кластер, архивный чейндж = продолжение территории); (2) формат требований O6 (requirement-format, в работе): `[#slug]` первым в буллете, деф-парсинг одним регэкспом `^- \[#[a-z0-9-]+\]` — «новое требование в адхоке» становится синтаксически однозначным: добавленная в спек-диффе строка `- [#slug]` внутри fileless-контракта. Pre-push чек над диапазоном закрывает то, что per-commit хук не видит; локальная история может быть неканонической, публичная обязана — пересборка перед пушем, трейсибилити через reflog + указатель в переписанных коммитах.

## Requirements

- Трейлер `Adhoc: <name>`: fileless-contract обязан нести `Adhoc:` + тело (замена текущего «непустое тело» в `#adhoc-body`); id резолвится через known-entities (новый или архивный чейндж — продолжение со спавн-семантикой); висячий id — ошибка. Дамп + README-норма с `[#adhoc-id dump]`.
- Рендер: адхоки группируются по id (число коммитов в кластере); реконструированный док кластера = конкатенация тел в порядке коммитов (`caped change show <id>` — через change-show); ренейм-события (R ideas/→ideas/ в диффе коммита) исключаются из списка адхоков; метрика «N id, M кластеров >2 коммитов» — view, а не абстракция.
- Pre-push чек (`caped check push` / шим pre-push в init, та же схема `exec caped hook`) над origin..HEAD, роллаут advisory → blocking: (а) новые `[#slug]`-def'ы в спек-диффах fileless-контрактов (по O6 — строка `- [#slug]`) → «новое требование в адхоке — заведи файл»; снятие def'ов — тоже; (б) `Adhoc: X` ≥3 раза → материализуй `changes/X.md` из сообщений; (в) контрактные правки спек без новых сценариев в тестах; (г) range-level trace (dump-атрибутные def'ы без цитат в дампе); (д) «в работу» без рабочих коммитов; (е) handoff-след: источник в диапазоне сказал «handed off → B», а в B нет следа (упоминания/требования в его файле) — ворнинг (промоут O1 из архивного handoff-findings).
- Пересборка перед пушем: процедура — split/материализация тел адхоков в файлы (сообщения переезжают в Provenance); переписанные коммиты несут указатель «reassembled from Adhoc: X,Y»; чек верифицирует: каждый id прошлого диапазона либо жив (≤2 коммитов), либо материализован в `changes/<id>.md` — тихая потеря = ошибка; reflog — локальный след.
- Тесты: hook (Adhoc: требуется на fileless-contract, кластер ≥3), render (группировка/док/эксклюзия ренеймов), check (new-def в адхоке, потерянный id при пересборке), secretary-e2e (агент при fileless-контракте ставит `Adhoc:` и пишет тело как мини-идею с основанием; находка про чужой контракт передаётся правкой цели — промоут O2 из архивного handoff-findings); `caped.sh trace` и `just test` зелёные.
- Видимость территории: свежие fileless-решения видны в survey-шаге (render-first) — план показывает «последние адхоки по Spec: <путь>», чтобы прибывающий/параллельный агент видел недавно тронутую территорию до действий (связка с multiagent-events).

## Decisions

- Адхок с id = append-only чейндж без файла (обсуждение 2026-08-23): мутабельная рабочая
  поверхность адхоку не нужна, решения точечные; виртуальный документ собирается из
  месседжей с общим `Adhoc:`-трейлером. Следствие для метрик — классификация точная по
  трейлеру, см. {#git-text-metrics}.
- O1 решён при реализации: `Adhoc:` обязателен на fileless-contract (contract, хук); internal — не
  энфорсится (именованные цепочки фиксов — конвенция, не правило).
- O2 решён частично: команда `caped check push` в v0, advisory, диапазон origin..HEAD; шим pre-push
  из init и каденция пуша — промоут в adhoc-verify.
- O5 закрыт: требование «адхок-выдержка» реализовано в render-format (acf7b98); полный док кластера —
  территория change-show (реконструкция сущности), контракт держит req 2.

## Rejected alternatives

- Кластеры по Spec:-хеуристике без явного id — отвергнуты: шумят на событиях-не-решениях (a11d6e6), не резолвят архивные чейнджи; явный трейлер однозначен и даёт резолв бесплатно.
- Количественная граница «>2 коммитов» по совести — количественная часть переходит машине (счётчик Adhoc: id в pre-push), совесть остаётся только на содержательной части (новый id на новой территории с вопросами — по-прежнему файл).
- Метрика «доля fileless-контрактов» как абстракция — заменяется view: кластеры по id и реконструированные доки.

## Provenance

Человек (дословно):

- «Я бы может просто заставил адхоку давать название как если бы он отдельным чейнджем и считать что весь коммит месседж это и есть файл этого чейнджа?… И тогда несколько последовательных адхок коммитов с одним айди как бы в один чейндж и слипаются мб, плюс можно указать айдишник уже архивированного чейнджа если там что-то упустили важное»
- «В целом получается чек должен ловить эти расхождения? Типа новое требование в адхоке? Если перед пушем его прогонять то агент все увидит и может пересобрать историю чтобы в публичной репе уже нормально все было (только тоже тут какой-то трейсабили нужен конечно)»
- «У нас кстати там формат требований зафиксировался - айди обязано первым в начале булета стоять (можешь посмотреть, по истории), мб это упростит проверку»

Додумано агентом (с основаниями):

- O6 делает «новое требование» синтаксически однозначным — основание: деф-парсинг `^- \[#[a-z0-9-]+\]` (зафиксирован в requirement-format, в работе); pre-push чеку не нужны эвристики «это требование или проза» — буллет с лидирующим id и есть требование.
- Жизненный цикл адхока выводится, а не хранится — основание: сообщения = виртуальный файл (конкатенация тел — derived doc, как остальные views); эскалация = переезд тел в файл, история не переписывается, сквош остаётся легитимным.
- Трейсибилити пересборки: reflog (локальный след) + указатель в публичных коммитах + машинная верификация «id не пропал молча» — основание: правило «чат эфемерен, променанс — нет» должно пережить rebase; без верификации тихая потеря адхок-ратионале неотличима от намеренной.
- История-доказательства класса нарушений: 5367bc4/578190d (новые требования файлlessly), a11d6e6 (ренейм в метрике адхоков), c8fcd49..5367bc4 (кластер из 5 fileless на одной спеке) — основание для требований 1–3; предметно подтверждает, что чек формализует уже случившееся, а не гипотезу.
- O1/O2 из архивного handoff-findings (dd060ac) промоутированы сюда — основание: были записаны только в файле чейнджа и умерли с архивом, нарушение #question-promotion / «silently deferred = lost»; промоут исправляет потерю, происхождение зафиксировано в этом променансе.
