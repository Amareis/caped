## Why

Второй живой харнес после dsh. Kimi Code — основная интерактивная сессия человека; без плагина
секретарская дисциплина там держится на AGENTS.md-указателе и доброй воле модели (после компакта —
уже нет). Мультиагентная картина ({#multiagent-events}) требует, чтобы ВСЕ агенты видели ленту,
а не только те, что под dsh.

## Context

Документация Kimi Code (hooks.html, plugins.html, август 2026): плагин = манифест
`kimi.plugin.json` + skills/agents/commands/hooks/mcpServers; ставится `/plugins install`
(локальный путь, zip, GitHub). Хуки: stdin JSON payload, exit 0 allow / 2 block, stdout в
контекст — контракт почти совпадает со скриптами dsh-плагина (порт, не изобретение).
Карта концепций dsh → kimi: дамп → `sessionStart.skill`/`systemPromptPath` (бюджет 32 КБ на
поле, 64 КБ суммарно); напоминалки → `UserPromptSubmit` (блокируемый); follow-up конца тура →
`Stop` (блокируемый, «модель продолжает тур» — сильнее напоминалки); экспорт траекторий →
`SessionEnd`/`TurnStarted`/`Notification` (наблюдательные); ре-инъекция после компакта →
`PostCompact`. Ограничения: плагины per-user на все проекты (проектного скоупа нет — хуки сами
проверяют `caped.registry` в cwd и молчат вне caped-реп); правки манифеста подхватываются после
`/plugins reload` или новой сессии.

## Requirements

- Манифест плагина: sessionStart-скилл «caped workflow» (указатель на `caped` + краткий ритуал,
  НЕ вшитая копия дампа — источник правды один, {#rules-in-cli}).
- Stop-хук: секретарский чек-лист конца тура (незаписанные решения? незакоммиченные файлы
  трекера?) — блок с текстом-продолжением при нарушении; fail-open по правилам платформы.
- UserPromptSubmit-хук: лёгкое напоминалку о `caped render plan` при старте работы в caped-репе.
- PostCompact-хук: ре-инъекция сжатого состояния (render plan head) после компакции.
- Все хуки no-op вне caped-реп (проверка registry в payload.cwd); таймауты ≤5с.
- Тесты: скриптовые прогоны хуков на фейковых payload (без живого kimi), плюс ручной смоук
  в реальной сессии.

## Decisions

- НЕ встраивать Kimi Code в dsh-харнес: dsh — для дешёвых API-агентов (DeepSeek/SiliconFlow),
  Kimi Code — интерактивный CLI с TUI; `kimi -p` ваншоты теряют интерактив, а ценность плагина —
  именно в живой сессии человека (решение из диалога 2026-08-24).

## Rejected alternatives

- MCP-обёртка над caped как единственная интеграция — хуки всё равно нужны для follow-up и
  компакта; MCP добавим позже, если понадобятся tool-вызовы (сейчас CLI достаточно).
- Запись дампа целиком в systemPromptPath — дрейф копии против `caped` как источника; скилл
  содержит указатель и ритуал, дамп печатается тулом.

## Provenance

Человек (дословно): «Хм, а в кими код плагин сделать сложно? Проще видимо вас через дипсик
харнесс уже запускать тоже?»

Додумано агентом (с основаниями): карта событий — по официальной доке (hooks.html: таблица
событий, блокируемость Stop/UserPromptSubmit; plugins.html: манифест, бюджеты промпта,
per-user скоуп). «Не сложно» — оценка по совпадению hook-контракта с уже написанными
dsh-скриптами (stdin JSON → exit code).
