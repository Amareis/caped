## Why

Два входящих релея подряд (tool-docs-flip-and-trace fa26a3a, backlog-autocreate-
at-init 68be0e4 — оба из kudach) прилетели с НЕканонической схемой: без секций
Context/Requirements/Decisions/Rejected/Open questions → наш `caped check` упал,
пришлось ремонтировать вручную по обоим. Доставка должна гарантировать валидность
на приёмке: каноническая схема — контракт релея, а не ручка приёмщика.

## Context

Канонический набор секций — Why/Context/Requirements/Decisions/Rejected
alternatives/Provenance/Open questions (caped check требует присутствие; контент
свежего скелета может быть «—»). Релей уже адаптирует файл (spawned_from: null +
Handoff); нормализация секций — то же семейство правок, считает сообщение
человека: «сделай чтобы релей делал чек идеи, чтобы она прилетала в нормальной
схеме сразу».

## Requirements

- `caped relay` перед коммитом у получателя: дополняет недостающие канонические
  секции пустыми (+«—»), затем прогоняет `caped check` в репо получателя; на
  красном — отказ релея с текстом «canonical schema not achieved».
- Локальный файл отправителя НЕ меняется (нормализуется копия-доставка).
- Тест: неканоническая идея → у соседа файл с полным набором секций и зелёным
  check; канонические релеи не изменены.

## Decisions

- Нормализация на КОПИИ: файл отправителя — факт его репы, доставка —
  гарантия получателю.
- Пустые секции с «—» валидны (скелет-семантика), content-ремонт — не дело
  релея (это уже думает получатель).

## Rejected alternatives

- Отказ релея без нормализации: ломает живые релеи (авторы внешних схем),
  вынуждает ручную последовательность «отправь → почини → переотправь».
  Отклонено.
- Валидация только после коммита: у получателя останется красный check на
  идее. Отклонено — гейт ДО доставки.

## Provenance

Человек (2026-08-24): «О, вот сделай чтобы релей делал чек идеи то? Чтобы она
прилетала в нормальной схеме сразу». Наблюдения агента: два живых релея
требовали ручного структурного ремонта (488d422, 6df5065-пред).
