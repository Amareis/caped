## Зачем

Статическая трассировка (spec-test-trace) отвечает «есть ли тест на требование», но не «проходит ли он».
Без статусов матрица покрытия врёт: тест существует и давно красный. Человек: «junit надо видимо в отдельную
идею вытащить тогда — иначе потеряется».

## Контекст

Вынесено из spec-test-trace по правилу «отложенный скоуп — находка»: там оставлен статический слой
(маркеры `[#<slug>]`, `caped trace`), сюда уходит всё, что требует запуска тестов. Статический слой не знает
языка проекта; статусный — тоже не должен, поэтому не парсим вывод раннеров, а читаем JUnit XML —
стандартный интерчейндж (cargo-nextest, pytest, jest, gotestsum умеют из коробки).

## Требования

1. Конфиг запуска — 1-3 строки на проект: `test_run` (команда прогона), `junit` (путь/глоб к XML),
   опционально `test_filter` (шаблон селективного прогона по маркеру).
2. Статус требования выводится из JUnit: все сценарии с его маркером зелёные → covered-green; есть красный →
   covered-red; есть маркер, но нет в отчёте → stale (переименовали сценарий — почти dangling, но живой).
3. Без конфига тул работает как сейчас — только статическая трассировка; статусный слой строго опционален.
4. render рендерит матрицу покрытия (требование → сценарии → статус) как view, не источник.
5. Селективный прогон затронутых требований (по диффу коммита/чейнджа) — post-v0.1, но конфиг `test_filter`
   проектируется сразу под него.

## Променанс

Человек: «неизвестно, какой язык на проекте и как тесты запускаются — какая-то система плагинов понадобится,
что ей надо? название и статус как минимум?»; «junit надо видимо в отдельную идею вытащить — иначе
потеряется. И это важный момент для воркфлоу, надо зафиксировать» (→ правило «отложенный скоуп — находка» в
README и дампе).

Агент (основания): JUnit вместо плагинов, потому что name/discovery — это grep по маркеру (бесплатно из
статического слоя), а status — чужой стандартный формат; плагин остаётся одной строкой конфига. Статус stale
отделён от dangling: dangling ловит удалённое требование, stale — рассинхрон имён при живом требовании.
