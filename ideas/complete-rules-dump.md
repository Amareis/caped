## Why

Bare-вызов `scripts/caped.sh` — единственное, что гарантированно читает агент adopting-репо (AGENTS.md сводится к указателю на него). Правило `[#trace-dump-attr]` держит нормы, помеченные `dump`, в дампе — но только если кто-то проставил атрибут. Обратная сторона не проверяется никем: норма агент-фейсинг **без** атрибута для trace невидима, и правило, существующее только в README, для агента не существует. Аудит README по дампу нашёл шесть таких норм; trace при этом зелёный (31/31) — дыры лежат глубже механизма, у требований просто не выставлен `dump`.

## Context

Слепой тест самодокументации (архивный secretary) уже находил дыры дампа этого класса — «дамп не отправляет читать реестр», противоречие «архивация без контента» vs «архив применяет дельты» и др.; те правки вошли в сам чейндж. Сегодняшние дыры — следующая ступень: не отсутствие текста, а отсутствие атрибутов у норм, которые в дампе обязаны быть. Метод находки: сравнение нормативного текста README (разделы «Требования», «События жизненного цикла») с текстом дампа, затем подтверждение grep'ом — темы squash/promotion/scratch/mutation/approve дают 0 вхождений в `scripts/caped.sh`.

Найденные пропуски дампа:

1. **Промоушн открытых вопросов** — README: «мелкий открытый вопрос отвечается прямо в чейндже и умирает с ним; вопрос, ставший работой, промоутится в идею (`spawned_from` фиксирует происхождение)». Дамп знает только «open questions → новая идея»; решение «вопрос ↔ идея» без правила промоушна остаётся на вкус агента: либо мусорные микро-идеи, либо молча потерянная работа.
2. **Мутации реестра капов** — README: «рождение/сплит/мерж капов — contract-коммит, трогающий `caped.registry`». Дамп описывает состояния (`legacy|declared|enforced`) и роллаут, но не то, как кап рождается/сплитится/мержится и какой трейлер при этом обязателен.
3. **Сквош чейнджа** — README: «сквош чейнджа легитимен, но тогда променанс — единственная оставшаяся история шагов». В дампе — ноль; агент, сквошащий патчсет, не знает, что именно променанс становится единственным носителем «почему».
4. **Кто пишет README капов и как он аппрувится** — README: «пишется агентом в момент чейнджа из слов человека; изменение README — бизнес-изменение, аппрувится человеком по диффу, поэтому README обязан быть достаточно мал, чтобы дифф реально читался». Дамп упоминает spec README только как получателя дельт при архивации.
5. **Скрэтч-материалы чейнджа** — README: «скрэтч-материалы большого чейнджа кладутся рядом и умирают при удалении» — нормы «куда класть промежуточное» в дампе нет.
6. **Гейт проверок перед архивацией** — README: «прогон trace — гейт перед архивацией: красный trace блокирует архив (в этом репо — через `just test`)». Дамп упоминает только trace; полный прогон (все suite'ы) — нет.

Корень один: у этих требований в README не выставлен атрибут `dump`, поэтому класс `undumped` их структурно не видит — та же граница, что у trace с требованием без маркера (полнота маркировки — территория `caped check`, ворнингом).

## Requirements

1. Дамп (`scripts/caped.sh`, bare-вызов) дозаполнить четырьмя нормами: промоушн открытых вопросов; мутации реестра капов (рождение/сплит/мерж — `Behavior: contract`, коммит трогает `caped.registry`); легитимность сквоша чейнджа с променансом как единственной оставшейся историей шагов; авторство и размер README капов (пишет агент из слов человека; мал, чтобы дифф читался; изменение README аппрувится человеком).
2. В README этим требованиям проставить `[#<slug> dump]`, чтобы полнота дампа удерживалась машиной — класс `undumped` в `caped trace`.
3. После правок: `caped.sh trace` зелёный, `just test` зелёный.

## Provenance

Человек (дословно):

- «Выполни скрипт, обдумай его, потом прочитай ридми и код и скажи - чего в выводе скрипта не хватает? Может какие-то правила забыли»
- «отлично. По процессу - куда все эти вопросы записать надо?»

Додумано агентом (с основаниями):

- Шесть пропусков дампа (п. Context) — основание: сравнение нормативного текста README с текстом дампа построчно; grep-подтверждение отсутствия тем (squash/promot/scratch/mutation/approve — 0 вхождений в `scripts/caped.sh`); trace при этом зелёный, что доказывает: дыры невидимы механизму из-за отсутствия атрибута `dump` у определений.
- Маршрутизация «куда записать»: новая идея, а не расширение чейнджа и не адхок — основание: живого чейнджа нет (`changes/` пуст, расширять нечего); работа трогает несколько капов (secretary: `scripts/caped.sh`; root: `README.md`), больше 2 коммитов, несёт открытые вопросы — каждый из этих признаков отдельно требует файл. `spawned_from: caped-rules` — территория дампа создана архивным чейнджем `caped-rules` (ca74832), ссылка на архивную сущность валидна по `caped check`.
- Пункт 6 (гейт `just test`) вынесен из требований в открытый вопрос, а не в требование — основание: прогон всех suite'ов — специфика этого репо (adopting-репа имеет свой runner), и AGENTS.md здесь уже несёт «run just test before archiving»; дублировать в дампе стоит только общую норму, если она есть.
- Скрэтч-материалы (п. 5) — кандидат на самую мелкую правку; оставлен открытым вопросом, не требованием, чтобы не раздувать скоуп (та же граница, что `check-marker-fullness`: ложное срабатывание хуже пропуска).
