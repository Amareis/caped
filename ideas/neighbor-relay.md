## Why

Ручной релей идей между репами уже повторён трижды (e2e-guard-retire — к нам,
idea-edited-consumer и kimi-code-plugin — к соседу), каждый раз вручную: скопировать
файл, адаптировать фронтматер, коммит с `Idea:` в чужой репо, снять локальную копию.
Процедура не формализована: ни списка соседей, ни команды, ни вывода в туле —
прибывающий агент не знает топологию проекта.

## Context

Живой кейс 2026-08-24: caped-context (dsh-плагин) — сосед без remote, его сессия
просыпается по idea-born своей ленты и закрыла релей idea-edited-consumer целиком
(архив ef251eb + адхоки feed-unknown-json, intent-from-events). Соседская сторона
готова; наша — процедура вручную. Мультирепа-топология принадлежит репо, а не тулу:
в bare-дамп (нейтральность, {#dump-neutrality}) список соседей не входит — это
данные репо, как `caped.registry`. Формат данных — файл в корне по образцу реестра
(TAB: имя, путь, роль), конфиг-алия вне дерева отвергается (прецедент «конфиги не
используем» — там про CLI-настройки; список соседей — данные топологии, как реестр).

## Requirements

- Файл соседей (например `caped.neighbors`, TAB: name, path, role) в корне репо;
  `caped check` валидирует формат.
- `caped relay <сосед> <идея>`: копирует `ideas/<name>.md` в `<путь соседа>/ideas/`
  с адаптацией (spawned_from: null, заметка о релее из этого репо в Context/Provenance),
  коммит там `Idea: <name>` (их хук энфорсит), затем по умолчанию снимает локальную
  копию (`Archives: <name>` + причина); флаг `--keep` оставляет локальную.
  Проверка: сосед — капед-репо (.git + registry), имя свободно у соседа.
- Вывод: `caped plan` показывает соседей (имя, путь, роль) — полнота сведений о
  проекте; отдельная команда/вид не обязательна в v0.
- Релей виден в нашей ленте событий: снятие локальной копии событится (см. пробел
  «withdrawal не эмитится» — общий с мультиагентной картиной).

## Decisions

- Данные соседей — файл в дереве (по образцу `caped.registry`), не `.caped/`-конфиг:
  топология — факт репо, коммитится, виден в плане; хидден-конфиг дрейфовал бы.
- `--keep` по умолчанию? Нет: «хэндофф идей» = передача владения, локальная копия
  снимается (прецедент kimi-code-plugin); `--keep` — для случая «у соседа своя идея,
  у нас своя» (idea-edited-consumer).
- Команда ходит напрямую в рабочее дерево соседа (у соседей нет remote — живой кейс),
  не через fetch/push.

## Rejected alternatives

- Продолжать вручную: процедура повторена трижды, каждая переносит ошибки (адаптация
  фронтматера, забытый `Archives:` на нашей стороне). Отклонено.
- Синхронизация через общий remote (fetch/push): у соседей remote нет; топология —
  локальные рабочие копии. Отклонено.
- `.caped/neighbors` (скрытый конфиг): невидим в плане без отдельного рендера, дрейф
  вне дерева. Отклонено в пользу коммитимого файла.
- Класть список соседей в bare-дамп: нарушает нейтральность дампа, данные репо не
  переносятся. Отклонено.

## Provenance

Человек (дословно, 2026-08-24): «Еще одна идея - как нам формализовать нашу текущую
мультирепа структуру? Чтобы например хэндоф идей соседу можно было делать через cli
тоже? И чтобы это тоже в выводе тула было для полноты сведений о проекте и соседях?»

Додумано агентом (с основаниями): файл-данные по образцу реестра, а не конфиг —
основание: топология — факт репо (реестр уже так работает, neutralize); ручные релеи
— 3 прецедента (см. Why).
