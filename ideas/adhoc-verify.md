## Why

v0 adhoc-lifecycle реализовал ядро (трейлер `Adhoc: <name>`, кластеры в рендере, `caped check push` с new-def и кластером ≥3, видимость в плане). Остаток — не оставить «пережившим архив» (question-lifecycle): пересборка истории с трейсибилити — главное из человеческого замысла («пересобрать историю, чтобы в публичной репе уже нормально всё было»), расширения чека, каденция пуша и e2e-доказательства.

## Context

Промоут из changes/adhoc-lifecycle.md (O2-хвост, O3, O4 + req 4 + req 5-e2e). Связки: `caped check push` уже в v0 (advisory, origin..HEAD) — здесь расширяется; `change-show` держит полный док кластера (не дублируем); `multiagent-events` — тот же класс «параллельные агенты», merge-исключение согласовать с ним; `git-text-metrics` — точная классификация по трейлеру уже даёт ему чистый вход.

## Requirements

- Шим pre-push в `caped init` (та же схема `exec caped hook pre-push`), делегирующий `caped check push`; роллаут advisory → blocking; ручная команда остаётся для skip.
- Пересборка: процедура в дампе (split/материализация тел адхоков в файлы, указатель «reassembled from Adhoc: X,Y» в переписанных коммитах); машинная верификация в `caped check push`: каждый id диапазона либо жив (≤2 коммитов), либо материализован в `changes/<id>.md` — тихая потеря = ошибка; reflog — локальный след для человека.
- Расширения `check push`: (в) контрактные правки спек без новых сценариев в тестах, (г) range-level trace (dump-атрибутные def'ы без цитат в дампе), (е) handoff-след: «handed off → B» в променансе источника без следа в B — ворнинг.
- Merge-исключение мультиагентных пушей (O4): диапазон с merge-коммитами — как хук (MERGE_HEAD/механический merge), согласовать с multiagent-events.
- secretary-e2e: два сценария — агент при fileless-contract ставит `Adhoc:` и пишет тело; находка про чужой контракт передаётся правкой цели (этикет handoff).
- Тесты: hook/render/check добавочные; `caped.sh trace` и `just test` зелёные.

## Rejected alternatives

- Верификация «до/после» через reflog как обязательная — отвергнута в v0.1-план: текущее состояние машиной (просто, детерминированно), reflog — человеку/дрейф-ревью (O3 из adhoc-lifecycle, рекомендация сохранена).
- Всё расширение сразу в v0 — отвергнуто при реконсиляции: push-каденция и e2e-харнес не успевали, вопрос-lifecycle обязал промоут, а не раздувание чейнджа.

## Provenance

Человек (дословно):

- «В целом получается чек должен ловить эти расхождения? Типа новое требование в адхоке? Если перед пушем его прогонять то агент все увидит и может пересобрать историю чтобы в публичной репе уже нормально все было (только тоже тут какой-то трейсабили нужен конечно)» — пересборка + трейсибилити, ядро этой идеи
- «Второй агент на стопе пока - сделай адхок дисцилину»

Додумано агентом (с основаниями):

- Промоут из adhoc-lifecycle (O2-хвост, O3, O4, req 4, req 5-e2e) с spawned_from: adhoc-lifecycle — основание: question-lifecycle («вопрос, ставший работой, промоутится в идею; иначе умирает с архивом»), инцидент O1/O2 handoff-findings как урок.
- «reassembled from Adhoc: X,Y» + верификация текущего состояния — основание: правило «чат эфемерен, променанс — нет» обязано пережить rebase; проверка по текущему состоянию детерминированна и дешёва, reflog не гарантирован после GC.
- Шим pre-push и e2e — отдельной каденцией (v0.1): шим меняет границу пуша у всех adopt'ов (роллаут осторожно), e2e — живые LLM-агенты (харнес-затраты); оба не блокируют ядро v0.
- Merge-исключение — с multiagent-events: общий «параллелизм» класс, решать вместе, не двумя заплатками.

## Open questions

- O1: каденция пуша — pre-push шим включать по умолчанию при init (advisory) или require флаг (`--with-push-check`)? Рекомендация: по умолчанию advisory, блокировка — роллаутом.
- O2: (в) «контракт без сценариев» — критерий «новые сценарии в этом же чейндже/диапазоне» распознаётся надёжно? v0.1-эвристика: файл теста с маркером нового def'а в диапазоне; точность — ворнингом.
