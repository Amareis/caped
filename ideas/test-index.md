## Why

Trace отвечает «есть ли ссылка на маркер», но не показывает, ЧТО за тесты стоят за требованием: названия сценариев и их doc-комментарии живут только в `tests/`. Обещано в README-«Впереди» («индекс тестов: doc-комменты + имена; тесты остаются в tests/ с маркерами, README капа ссылается»), идеей не было — записано аудитом 2026-08-23. Статусы прохождения — отдельная идея (test-status-junit), здесь только статический индекс.

## Context

Данные для индекса уже размечены: сценарии несут `[#<slug>]` в именах/комментариях (норма trace-refs). Индекс — обратная проекция trace: от требования к списку его сценариев с комментариями. depends_on render-format — общий JSON-слой и тот же файл.

## Requirements

- `caped render tests [cap]`: по каждому маркеру enforced-капы — список сценариев (файл, имя, doc-комментарий), сгруппированных по требованиям; `--json` по общей схеме.
- Парсинг — тот же grep-уровень, что у trace (без языковых плагинов): маркер в имени сценария или комментарии + ближайший doc-комментарий.
- Тесты: фикстурные тест-файлы с маркерами в `tests/render/test_render.sh`, ассерты по группировке.
