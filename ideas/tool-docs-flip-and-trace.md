## Why

Первый боевой флип капы в enforced (kudach, web-version) показал: процесс
пришлось реверс-инжинирить по скриптам вместо чтения правил тула. Три
конкретных провала документации и одно пожелание.

## Что было неочевидно

1. **Хук читает реестр из рабочего дерева, не из HEAD.** Правка
   `caped.registry` «включает» enforced-режим мгновенно, до коммита: агент
   отредактировал реестр заранее и получил отказ на подготовительном коммите
   (маркеры/тесты), который контрактом не являлся. Пришлось откатывать реестр
   и делить флип на два коммита.
2. **Флип можно и удобно делать ОДНИМ коммитом** — README капы + маркеры +
   реестр + чистка рефереров с `Behavior: contract` + `Spec:`: требование
   хука тут не мешает, а ровно описывает происходящее («устанавливаю
   контракт»). Подготовительные коммиты (маркеры, тесты) возможны сколько
   угодно, пока капа не enforced — но делить ради деления смысла нет:
   маркеры без контракта бессмысленны. Это стоит зафиксировать как
   документированную процедуру флипа (1. готовим сколько угодно коммитов,
   2. один контрактный коммит-флип, 3. не трогаем реестр раньше времени).
3. **Зона сканирования refs и ложные срабатывания.** Trace считает ref'ом
   паттерн `[#word]` в ЛЮБОМ tracked-файле (кроме спек/идей/чейнджей),
   включая обычные комментарии и строки. Поймано два ложных: URL-фрагмент
   `vk.ru/app<id>[#payload]` в doc-комментарии и ссылка на идею
   `[#neighbor-relay]` в комментарии caped.neighbors — оба уронили trace в
   RED (dangling). Стоит прямо предупредить в правилах: «паттерн `[#word]`
   где угодно = trace-ссылка, избегай в прозе/URL», и/или сузить сканирование
   (например только код-тесты, или строгий word-boundary slug-формат).
4. **Синтаксис атрибутов маркера.** `no-test`/`dump` пишутся внутри скобок
   (`- [#slug no-test dump]`) — это есть в README caped, но не в rules-дампе
   тула; агент вытащил из regex'а caped-trace.sh.

## Пожелание

Эталонный README enforced-капы в доке тула (или генератор
`caped init-cap <name>`, создающий скелет с ## Requirements и парой
буллетов-примеров) + одна строка про границу ответственности:
`caped check` = контент/фронт-маттер, `caped trace` = покрытие требований
тестами.
