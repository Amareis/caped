## Why

README капы обязаны ссылаться на архивные чейнджи («зачем, текущие инварианты, ссылки на архивные чейнджи») — сегодня это ручной список, который дрейфует. История фичи выводима из гита: пути капы из реестра + трейлеры + `git log --follow`. Обещано в README-«Впереди», идеей не было — записано аудитом 2026-08-23.

## Context

Кирпичи те же, что у change-show (трейлеры, `--follow`), но единица — капабилити (префикс реестра), не сущность трекера. Пересечение: contract-коммиты капы несут `Spec: <путь>` и часто `Change:` — свзяь «коммит ↔ чейндж» бесплатна. depends_on render-format — общий JSON-слой и тот же файл.

## Requirements

1. `caped render feature <cap>`: хронология коммитов, трогающих prefix капы, сгруппированная по чейнджам (по `Change:`-трейлеру); адхоки капы — отдельной секцией.
2. README капы ссылается на `caped render feature <cap>` как на живой индекс, а не на ручной список архивов.
3. Тесты в `tests/render/test_render.sh`: фикстурный реестр + коммиты по двум капам, ассерты по группировке.
