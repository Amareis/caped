## Why

Адхок-дисциплина сознательно кладёт ратионале решений в тела коммитов, а не в файлы. Значит,
значимая часть «спеки» проекта физически живёт в гит-истории, и объём этого слоя нигде не виден.
Без метрики нельзя ни оценить, сколько знания потеряется при потере истории (squash, фильтр,
переезд репы), ни заметить перекос «решения принимаются мимо трекера».

## Context

Замер на репе тула (2026-08-23, 115 коммитов): тела коммитов ≈ 25 КБ + сабжекты ≈ 11 КБ —
сопоставимо со ВСЕМ корпусом спек (~1.3k строк). Адхок-коммиты (трейлер Behavior: без Change:):
16 шт, 5.7 КБ ратионале, существующего только в гите. Классификация тривиальна по трейлерам,
которые уже энфорсит хук: Behavior без Change — адхок, с Change — работа по чейнджу, без
Behavior — свободная зона. Смежные идеи: {#feature-history} (история капабилити из гита),
change-show (досье чейнджа из истории) — эта метрика тот же источник данных, но сводный вид.

## Requirements

- Новый view (например `caped render stats` или секция в coverage): строки кода, тестов,
  спек-файлов (README капов + ideas/ + changes/) и текста коммит-месседжей — в разрезе
  адхок / чейндж-работа / свободная зона (классификация по трейлерам хука).
- Адхок-объём показывается отдельно: это единственный класс знания, не дублированный в файлах.
- Всё считается из локального гита и рабочего дерева, без сети; плейнтекст по умолчанию,
  --json по общему правилу {#render-json}.

## Decisions

- Онтологическое уточнение (обсуждение 2026-08-23): файл чейнджа и коммит-месседж различаются не
  местом хранения (после архива оба живут только в гите — файл вообще `git rm`'нут), а свойствами
  ПРИ ЖИЗНИ: файл мутабелен и адресуем (рабочая поверхность), месседж заморожен и append-only.
  С введением `Adhoc: <id>` ({#adhoc-lifecycle}) адхок — это append-only чейндж без файла;
  классификация коммитов для метрики становится точной по трейлеру вместо эвристики
  «Behavior без Change», а метрика измеряет «заморожено в логе vs ещё на рабочей поверхности».

## Provenance

Человек (дословно):

- «Хм. Ну получается нужна еще одна метрика — количество текста в гите? Особенно в адхок коммитах»

Додумано агентом (с основаниями):

- Классификация коммитов по трейлерам Behavior/Change — основание: хук уже энфорсит оба,
  машиночитаемость бесплатна; замер подтвердил разделимость (16 адхок из 115).
- Приоритет low и размещение в render — основание: метрика наблюдательная, не блокирует
  процесс; render — единственный генератор view по норме производных.
