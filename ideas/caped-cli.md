## Why

Шелл-диспетчер несёт дубль семантики: текст правил в `caped.sh` и сообщения ошибок хука — два источника одной
семантики (зафиксировано как открытый вопрос caped-rules, принято в v0). Бинарь схлопывает дубль и даёт
предсказуемый старт хука.

## Context

Шимы уже поставлены в финальной форме (`exec .../scripts/caped.sh hook commit-msg`) — при переходе на бинарь
меняется только диспетчер, шимы и AGENTS.md adopting-репо не трогаем. Интерфейсные тексты — на английском
(решение из caped-rules).

## Requirements

- Один бинарь `caped` с сабкомандами init/hook/check/render, семантика 1:1 с шелл-версией.
- Текст правил — один источник в коде: bare-дамп и сообщения ошибок хука генерятся из него.
- Репо тула продолжает жить по своей схеме; реестр пополняется капами тула (hook, registry, index-gen,
   report) — с фасадами, пилот публичных интерфейсов уже на своём коде.
- Команды-обёртки над событиями лайфцикла: `caped idea|work|archive <name>` конструируют коммиты с правильными
   трейлерами — снимают опечаточную поверхность ручного набора (полевое наблюдение: трейлеры пишутся руками).
- Миграция: init обновляет шимы на `exec caped hook ...`; шелл-скрипты удаляются архивным коммитом чейнджа.
- Встроенные meta-доки при сборке (обобщение бандла чейнджлога, tool-changelog): build-time дамп туловых derived-вьюх — changelog (готов), история тула, рекосы и покрытие tool-репо — пакуются в бинар; версия-константа уже на этом механизме (`caped version [--changelog]`). Per-repo вьюхи (план/history/reqs/coverage ТЕКУЩЕГО репо) в бинарь НЕ печём — выводятся живьём: «идеальная дока» = снапшот туловой стороны + живой вывод по репо.

## Provenance

Агент: порядок depends_on (check/test-hooks/render до cli) — бинарь без verify-инфраструктуры придётся
тащить всё разом, а так каждая часть уже отдогфужена в шелле. Язык реализации открыт (rust — по аналогии с
kudach-стеком; но тащить rust-рампу ради 300 строк логики — вопрос).

## Open questions

- Язык бинаря: rust vs go vs ... — критерий: время старта хука и порог контрибуции.
- Дистрибуция: cargo install vs готовые бинари vs git-submodule со скриптами навсегда для v0-режима.
- Миграция с шелл-установки: у человека на машине стоит симлинк `~/.local/bin/caped -> ~/work/caped/caped`
  (shell-wrapper, 2026-08-23) и linked-шимы в adopting-репах с абсолютными путями на `~/work/caped/scripts/`.
  При появлении бинаря: симлинк удалить/перенацелить на бинарь, в каждой linked-репе перепрогнать `caped init`
  (починит шимы идемпотентно). Не забыть.
