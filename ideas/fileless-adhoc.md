## Зачем

Полевое использование показало: четырёхкоммитный минимум (идея → mv → работа → архив) — ритуал для решений,
принятых за одно сообщение в диалоге. Файл нужен вещам, которые бродят и зреют; адхоку достаточно
гит-мессаджа, где «почему» можно расписать подробно.

## Контекст

Ключевая прикидка реализации: **fileless уже почти работает**. Хук требует файл только при трейлерах
`Change:`/`Idea:`/`Archives:` или задетом `changes/`; коммит с `Behavior: contract` + `Spec:` без файла легален
сегодня. Пробелы: (1) ничто не заставляет нести мотивировку в теле — «почему» снова испаряется; (2) нет
правила «когда файл обязателен» — без него всё скатится в адхок; (3) views (архив) не покроют fileless —
решения ищутся по `git log` (трейлеры `Behavior: contract` + `Spec:` — якоря поиска).

## Требования

1. Fileless-адхок легален: коммиты с `Behavior:` (+`Spec:` на contract) без файла сущности; тело коммита
   обязано нести мини-променанс (мотивировка, цитата, основание). Хук энфорсит: `Behavior: contract` без
   `Change:` требует непустого тела сообщения (предметная строка и трейлеры не считаются).
2. Порог обязательного файла (задокументирован в дампе и README): работа > 2 коммитов; новая территория
   решений; спорное или необсуждённое; затрагивает несколько капов; есть открытые вопросы. Нарушение порога —
   территория дрейф-ревью, не хука.
3. Финиш чейнджа может быть одним коммитом (дельты + удаление файла + `Archives:`) — явно задокументировать;
   раздельный финиш остаётся валидным.
4. Риск «всё становится адхоком» — метрика для дрейф-ревью: доля fileless contract-коммитов.

## Променанс

Человек: «для таких адхок решений я бы вообще убрал файл — у нас есть гит мессадж, где такие вещи можно
расписывать подробнее; файлы больше нужны для больших вещей».

Агент (основания): единственный новый энфорс — непустое тело (контент не проверить хуком, граница «хук vs
совесть» как со спеками); порог через дрейф-ревью, а не хук — количественные правила в хуке дают ложные
срабатывания на легитимных цепочках (аналогия: почему хук не проверяет контент спеки); пункт 3 — из полевого
наблюдения, что дважды финиш делался церемоннее, чем требует модель.

## Открытые вопросы

- Нужен ли slug-трейлер (`Adhoc: <slug>`) для поиска/группировки, или достаточно `git log --grep` по телу?
  Склонность: не нужен, slug в subject'е читается глазами и грепом.
- Мерить ли долю fileless в coverage-отчёте materialise — туда же, в дрейф-ревью.
